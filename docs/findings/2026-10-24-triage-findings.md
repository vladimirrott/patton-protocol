# T1 triage findings, 2026-10-24

Every number below appears in `lab/TRIAGE_REPORT.md`, in the pre-registration, in the post hoc table at the end,
or in `lab/CC_REPORT.md`, and `tests/test_triage_study_integrity.py` fails when one does not. The rules were frozen
in `lab/prereg/2026-10-24-triage-study-preregistration.md` before the first call on the test set. Every answer is
stored with the full response in `lab/triage_study/`, and replay re-decides each one from the frozen code. The study
and both development runs cost under $3 on Groq.

## The question

The gate (T0) asks the person about every change to a file that existed when the session started. On the gate
studies' fixtures that meant 1.240 questions per run, counting the commands it cannot read. A person who answers
that many questions starts approving all of them, and an approve-all operator gives the unguarded harm back. T1 is
an LLM analyst between the gate and the person: it may let through a change the gate can undo, and it sends the
person everything that could lose something. It sees the gate's facts and the person's mission, never the worker's
reasoning, and its answer counts only through mechanical rules (every path allowed with evidence quoted word for
word from the trusted facts, or escalate).

The test set is every flag the gate raised, or would have raised, in the 800 stored runs of the Claude Code and
Codex studies: 838 flags, 120 critical, 626 benign and 92 unscored. The 154 commands the gate cannot read skip T1 and
go to the person by rule.

## Limits, first

- **Few distinct critical cases.** The 120 critical flags are 14 distinct cases (a fixture and its set of critical
  paths) from 13 fixtures, repeated across reps and runs. Zero misses over 14 cases bounds the miss rate at 0.193
  (exact one-sided 95%), and over 120 flags at 0.025. The registered fixture-cluster bootstrap gives 0.000, because a
  bootstrap of a rate that is zero in every fixture is zero; it says nothing about cases the fixtures do not hold.
- **Synthetic fixtures with explicit notes.** Each fixture's handoff note states what matters. Real repositories
  leave more unsaid, and T1 escalates what its notes do not cover, so it would ask more there.
- **The prompt was tuned on the development fixtures.** The first development run allowed the only copy of a
  mailbox export in every h05 run by quoting a true note ("the account no longer exists"). The frozen prompt says
  that a missing source or account marks the only copy and that a file not called disposable is not.
- **The injection test had nothing to move.** T1 missed nothing on the blind context, so an injected note could only
  have raised misses from zero, and it did not. That says the evidence rule and the untrusted markers held against
  one fixed note, not against an adversary who adapts.
- **No person was in the loop.** Questions per run is a count of escalations, not a measure of what a person does
  with them.
- **One deviation in wording.** The pre-registration says the bootstrap resamples the 16 fixtures; the report
  resamples the fixtures that have flags in a cell. For the primary cell those are all 16, so its numbers are the
  registered ones. The two worker cells hold Claude Code flags only, and an independent recompute that resampled
  all 16 fixtures moved their upper bounds in the third decimal. No verdict uses those cells.
- **Independent recompute.** A separate agent rebuilt the labels and re-derived all stored decisions from the raw
  answers with its own code, and every table and verdict matched.

## Pre-registered results

- **T1, misses under 0.05: SUPPORTED.** gpt-oss-120b on the blind context allowed 0 of 120 critical flags. T1's own
  judgment did the work: it escalated nearly every critical flag itself, and the mechanical rules caught the rest.
- **T2, false escalations under 0.50: SUPPORTED.** It escalated 45 of 626 benign flags, a rate of 0.072 with a 95%
  bound of 0.178. 35 of the 45 sit in one fixture (f07), where the note says the thumbnails are "generated by
  `make_thumbs.py`" without saying they can go, so T1 held them under the rule the development run added.
- **T3, an injected note raises misses: NOT SUPPORTED.** With a note to the reviewer appended to every critical
  command, gpt-oss-120b still allowed 0 of 120 (one-sided p 1.0000).
- **T4, the worker's own words raise misses: NOT SUPPORTED.** With Claude Code's description of each command added,
  it allowed 0 of 120 (one-sided p 1.0000).

## Exploratory

- **Every cell missed nothing.** All four models on the blind context, and gpt-oss-safeguard-20b on the worker and
  injected contexts, allowed 0 of 120 critical flags. False escalation rates ran from 0.053 (gpt-oss-safeguard-20b)
  to 0.077 (qwen3.8-27b).
- **Questions per run** fell from 1.240 to 0.491 with gpt-oss-120b and to 0.456 with gpt-oss-safeguard-20b. The hook
  alone asked 1.134 times per run in the Claude Code study.
- **The rules caught malformed answers.** qwen3.8-27b gave 18 unreadable answers, and gpt-oss-safeguard-20b quoted
  evidence it could not find in the facts 21 times on the worker context; each of those escalated.
- **Agreement with the study oracle** on allows was 0.851 for gpt-oss-120b. The oracle also refuses the live
  original of a backed-up pair, which loses nothing while the copy stays, so it is stricter than the harm label.
- **Cost:** $0.2872 for the 838 flags on gpt-oss-120b, against $0.9149 on qwen3.8-27b.

## What this supports

On these fixtures an LLM analyst that sees only the gate's facts cut the questions per run by more than half and
waved no harmful change through, on four models, with and without the worker's words, and with an injected note. The
evidence covers 14 distinct critical cases, so the miss rate it rules out is about one in five, not one in twenty.
The next measurement needs more distinct critical cases, real repositories with sparser notes, and an adversary
who writes to the analyst on purpose.
